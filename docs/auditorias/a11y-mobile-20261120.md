# Auditoría de accesibilidad móvil — 2026-11-20

**Audiencia**: PO · **Autor**: auditor.
**Objetivo**: inventario de problemas específicos de mobile 375x667 (iPhone SE baseline) + hallazgos que la auditoría general [a11y-core-20261119.md](a11y-core-20261119.md) no capturó. Foco: viewport chico, qué se desborda, qué es imposible de tocar, qué textos quedan ilegibles.
**Método**: análisis estático del código responsive + inspección de clases Tailwind + heurísticas WCAG 2.2 "Target Size (Minimum)" (criterio 2.5.8 nuevo). Zero navegación real (regla cero-prod con cuentas); test real debe hacer PO con DevTools responsive o dispositivo real.

---

## Baseline viewport mobile

Target primario: **375x667** (iPhone SE 2020/2022, viewport más chico en uso real en Chile aún). Secundario: **390x844** (iPhone 13/14/15). Android: **360x800** típico.

Elementos críticos:
- **Target size WCAG 2.5.8**: ≥24px (nuevo criterio 2.2) o ≥44px (criterio 2.5.5 legacy). Tailwind: `h-11` (44px) o `min-h-[44px]`.
- **Texto legible**: ≥16px body (evita zoom automático en iOS Safari).
- **Contraste**: ya cubierto en [a11y-core-20261119.md](a11y-core-20261119.md).

## Hallazgos por URL

### 1. Home `/`

**Observaciones** (del código `pages/index.tsx` + `SearchBar.tsx`):

- **M-H-01 [MEDIO]**: SearchBar en hero usa dropdown custom para categorías/comunas. Verificar que el dropdown se renderiza contained en viewport (no desborda a la derecha en mobile). Grep muestra portal rendering con posicionamiento absoluto — riesgo de desborde.
- **M-H-02 [BAJO]**: Hero image (si existe) ocupa el 100% width. Verificar aspect-ratio en mobile (puede comer el fold completo).
- **M-H-03 [BAJO]**: Bloques "Cómo funciona" (StepCard) en columna 1 en mobile. OK por default responsive.
- **M-H-04 [MEDIO]**: `PrelaunchDemandCapture` form en home (L26 pages/index.tsx) — `flex flex-col sm:flex-row`. En mobile stack vertical. OK. Verificar que el select "Mi comuna..." no sobresalga (`h-12` ok ≥44px).

### 2. Explorar `/explorar`

**Observaciones** (del grep `pages/explorar.tsx`):

- **M-E-01 [BLOQUEA]**: Filtros en desktop están en sidebar lateral (`lg:block w-72 shrink-0 sticky top-24`) — invisible en mobile (`lg:hidden` + botón fab fixed). Verificar que el fab y el drawer sheet son tapeables + no quedan debajo del header.
- **M-E-02 [MEDIO]**: Chips de filtros aplicados (debajo del grid) con botón `×` de dismiss (línea 751) tamaño chico. Verificar que es ≥44px.
- **M-E-03 [BLOQUEA]**: Paginación "Anterior/Siguiente" (L973-1003) usa `hidden sm:inline` y `hidden sm:flex` → en mobile queda solo el ícono arrow. Verificar que los botones visibles son ≥44px con aria-label.
- **M-E-04 [MEDIO]**: Grid `grid-cols-1 sm:grid-cols-2 xl:grid-cols-3` → mobile 1 col. OK. Verificar que ServiceCard no desborda.
- **M-E-05 [MEDIO]**: Dropdown "Ordenar por" (L906) — `hidden sm:block` label. En mobile solo el select. Verificar que el select visible tiene label implícito (aria-label) para lector.
- **M-E-06 [BAJO]**: Vista Mapa (botones Lista/Mapa) — `hidden sm:inline` para el text, solo ícono en mobile. Verificar aria-label.

## Hallazgos sistémicos cross-URL

### S-M-01 [BLOQUEA] — Tap targets < 44px

Grep muestra `h-11`/`h-12`/`min-h-[44px]` solo en 10 archivos de los 50+ con botones. **Mayoría de botones no tienen tamaño explícito** → caen al default de Tailwind (`py-2` ~32px, `p-1` ~24px).

**Fix propuesto**:
- Button component shared (`components/UI/Button.tsx`) → agregar `min-h-[44px]` default.
- Audit visual de buttons ad-hoc en pages/components.
- Spec e2e con assertions `expect(btn).toHaveCSS('height', '44px' or more)` para botones de high-touch flows.

**Esfuerzo**: 1-2h audit + fix. **ALTA pre-campañas** — cada touch failure = frustración → abandono.

### S-M-02 [MEDIO] — Texto < 16px auto-zoom iOS

iOS Safari hace zoom automático al focus en input con `font-size` < 16px. Grep tentativo:

```
components/**/*.tsx | grep "text-sm.*input\|text-xs.*input"
```

**Riesgo**: focus en input con `text-sm` (14px) → iOS zoom → UI distorsiona.

**Fix propuesto**: todos los `<input>` + `<textarea>` + `<select>` en mobile debe tener `text-base` (16px) mínimo.

**Esfuerzo**: 30 min grep + fix. **MEDIA pre-campañas**.

### S-M-03 [BLOQUEA] — Horizontal scroll (desborde)

Elementos que pueden crear horizontal scroll en mobile:
- Tablas de admin (admin UI OK, no user-facing).
- Images sin `max-width: 100%`.
- Flex rows con `whitespace-nowrap` sin `overflow-x-auto`.

**Fix propuesto**: body con `overflow-x: hidden` como safety net + audit específico por página.

**Esfuerzo**: 1h audit + CSS global defense. **ALTA pre-campañas** (bug visible deja mala impresión).

### S-M-04 [MEDIO] — Safe area iPhone X+

Elementos `fixed bottom-0` sin `padding-bottom: env(safe-area-inset-bottom)` se cubren con la home bar de iPhone X+. Grep:

```
pages/explorar.tsx:578: <div className="lg:hidden fixed bottom-6 left-1/2 ...">
pages/explorar.tsx:600: <div ... className="lg:hidden fixed bottom-0 left-0 right-0 ...">
```

Dos fixed bottoms sin safe area padding → posible superposición con home bar iOS.

**Fix propuesto**: agregar `pb-[env(safe-area-inset-bottom)]` o Tailwind arbitrary value.

**Esfuerzo**: 15 min. **MEDIA pre-campañas**.

### S-M-05 [MEDIO] — Keyboard virtual tapa inputs

Mobile Safari + Chrome Android: al focus en input bajo del viewport, keyboard tapa el input. Patrón defensivo: `scrollIntoView({block: 'center'})` on focus.

**Fix propuesto**: handler `onFocus` en inputs de formularios bajo del fold (`register.tsx`, `mensajes`, etc.).

**Esfuerzo**: 1h. **MEDIA pre-campañas**.

### S-M-06 [BAJO] — Pinch zoom habilitado

Grep `viewport` en `_document.tsx` o `_app.tsx`:

Si contiene `user-scalable=no` o `maximum-scale=1` → accesibilidad bad (usuarios con baja visión no pueden zoom). Verificar.

## Script de test mobile sugerido

Para automatizar parte de la validación:

```js
// e2e/specs/a11y-mobile/tap-targets.spec.ts
import { test, expect } from '@playwright/test';

test.describe('A11y mobile — tap targets ≥44px', () => {
    test.use({ viewport: { width: 375, height: 667 } });

    test('todos los <button> primarios tienen height ≥44px en /explorar', async ({ page }) => {
        await page.goto('/explorar');
        const buttons = page.locator('button:visible');
        const count = await buttons.count();
        for (let i = 0; i < Math.min(count, 20); i++) {
            const btn = buttons.nth(i);
            const box = await btn.boundingBox();
            if (box && box.width > 20) {
                expect.soft(box.height, `Button #${i} at ${JSON.stringify(box)}`).toBeGreaterThanOrEqual(44);
            }
        }
    });

    test('no hay horizontal scroll en /home', async ({ page }) => {
        await page.goto('/');
        const bodyWidth = await page.evaluate(() => document.body.scrollWidth);
        const viewportWidth = await page.evaluate(() => document.documentElement.clientWidth);
        expect(bodyWidth).toBeLessThanOrEqual(viewportWidth + 5);
    });
});
```

Esfuerzo spec: 30 min. Puede correr post-launch como regression check.
