## Core Web Vitals por URL

### 1. Home `/`

**Estado actual**: Perf 90 mobile / 100 desktop. LCP 3.5s mobile (amarillo, umbral verde <2.5s), 0.8s desktop (verde).

**Hallazgos**:

- **H1-LCP-HOME**: LCP element en mobile probablemente es el hero image. Verificar que use `next/image` con `priority` + `sizes` correcto. Si la home tiene carrusel (post `home-carrusel` sprint), verificar que solo el 1er slide tiene priority (más de uno = waste).
- **H2-FONT-SWAP**: Outfit cargado via `next/font/google` self-hosted con preload (ver `lib/fonts.ts`). Óptimo. Cero acción.
- **H3-PRECONNECT**: `_document.tsx` ya tiene preconnect a Supabase Storage + Unsplash. Óptimo.

**Impacto perf <2h**: investigar LCP 3.5s mobile (podría ser el image del hero). Si el hero tiene `priority={false}` o sin `sizes`, agregar. ~30 min + medición. Impacto esperado: LCP 3.5s → 2.5-2.8s.

### 2. Explorar `/explorar`

**Estado actual**: Perf 77 mobile / 92 desktop. LCP 5.8s mobile (**POBRE**, umbral >4s), 1.9s desktop (verde).

**Hallazgos**:

- **H4-LCP-EXPLORAR-MOBILE**: LCP element = primera card de servicio con foto de Supabase Storage. En mobile las imágenes viajan grandes aunque la card sea 160×120px, porque sin el `sizes` correcto next/image sirve 1200w+. Ver si `components/Explore/ServiceCard.tsx` tiene `sizes` optimizado.
- **H5-SKELETON-CLS**: skeleton loader de las cards es `ServiceSkeleton`. Verificar que el skeleton tiene las mismas dimensiones que la card real (sin CLS al swap). CLS actual = 0, parece OK.
- **H6-RPC-LATENCIA**: `buscar_servicios` RPC con GRANT restaurado post bug P0 (hoy aterrizado). Tiempo de response ~500-800ms típico mobile 3G/4G. Difícil reducir sin índices nuevos.
- **H7-BUNDLE-EXPLORAR**: `pages/explorar.tsx` incluye filtros SidebarFiltros + SearchBar + mapa (si está activo). Probable bundle propio grande. Verificar con `npm run build` + reporte de bundle analyzer post-launch.

**Impacto perf <2h**: agregar `sizes="(max-width: 640px) 50vw, (max-width: 1024px) 33vw, 25vw"` a ServiceCard Image. ~15 min + medición. Impacto esperado: LCP 5.8s → 4-4.5s (aún no verde pero rango amarillo).

### 3. Perfil proveedor `/proveedor/{id}`

**Estado actual**: no se midió en 17-11. Estructura de la página incluye foto de perfil + galería + lista de servicios + reviews. Probable LCP = foto de perfil o primera card de servicio.

**Hallazgos (estáticos)**:

- **H8-GALERIA-LAZY**: `components/Servicio/ProveedorResumenCard.tsx` usa `next/image`. Verificar que fotos de galería más abajo del fold tienen `loading="lazy"` por default (next/image sin `priority` ya hace esto).
- **H9-MAP-LEAFLET**: si la página incluye mapa Leaflet, puede ser ~50KB extra de JS. Verificar lazy-load (dynamic import con SSR off).

**Impacto perf <2h**: medir con Lighthouse real (el PO puede correr `npx lighthouse https://www.pawnecta.com/proveedor/<uuid> --view` el viernes AM — 5 min).

### 4. Ficha servicio `/servicio/{id}` (con reviews)

**Estado actual**: Perf 71 mobile / 85 desktop. LCP 4.4s mobile (**POBRE**), 1.8s desktop (verde). CLS mobile 0.187 (**POBRE**, umbral >0.1), desktop 0.112 (**POBRE marginal**).

**Hallazgos**:

- **H10-CLS-MOBILE-FICHA**: diagnóstico pendiente del `layout-shifts.subItems.rootCauses` en el JSON Lighthouse. Hipótesis: (a) logo footer (fix `cls-footer` aterrizado pero puede no haber cerrado 100%); (b) imagen de hero ficha con dimensiones sin aspect-ratio fijo; (c) sección de reviews que se carga tarde desplazando el contenido.
- **H11-HERO-IMG**: [ServiceDetailView.tsx:856](../../components/Servicio/ServiceDetailView.tsx#L856) tiene `priority={fotoActiva === 0}` en el hero. Correcto. `fill` + `sizes` también OK (línea 841).
- **H12-GALERIA-MINIATURAS**: línea 961 — miniatura `width={64} height={64}` + `unoptimized={isPreOptimizedHost(foto)}`. Correcto, dimensiones fijas → cero CLS.
- **H13-REVIEWS-LATE-LOAD**: `Service/ReviewList.tsx` fetchea reviews client-side post-mount. Si el skeleton no tiene altura mínima, al cargar los reviews desplaza contenido abajo → CLS. Verificar.
- **H14-LCP-MOBILE-FICHA**: 4.4s mobile en pobre. Proviene del hero de foto del servicio. Mejoras incrementales (compresión fotos subidas por proveedor, fetch priority) pueden bajar 1-2s.

**Impacto perf <2h**:
1. Diagnosticar CLS 0.187 mobile vía JSON Lighthouse (`rootCauses`). 15-20 min. Si causante es trivial (imagen sin dimensión fija en reviews o hero) → fix ~30 min.
2. Asegurar `min-height` en el skeleton de `ReviewList` si no lo tiene. ~10 min.

### 5. Mensajes `/mensajes` (con conversaciones)

**Estado actual**: sin baseline (requiere login).

**Hallazgos (estáticos)**:

- **H15-FETCH-CONVS**: la lista de conversaciones se fetchea client-side. Si el user tiene 20+ convs, el fetch puede tardar. Sin fallback visible.
- **H16-REALTIME**: Supabase Realtime abre WebSocket al mount. Overhead ~100-200ms. Difícil evitar — es feature core.
- **H17-KILL-SWITCH**: pendiente de `MessageThread.tsx` sin kill-switch 5s (ver `docs/auditorias/error-handling-20261119.md #4`). Impacto perf cero; impacto UX al colgarse.

**Impacto perf <2h**: fetch de conversations idealmente SSR. Hoy es client-side. Fix SSR es sprint propio (~3-4h, no cabe en <2h).

## Hallazgos cross-URL

### Fuentes

- **FONT-OUTFIT**: `next/font/google` self-hosted + preload. Óptimo (ya en `lib/fonts.ts` + `_document.tsx`). Cero acción.

### Imágenes

- **IMG-NEXT-IMAGE**: `next/image` usado en los componentes clave (Header, Footer, ServiceCard, ServiceDetailView, galleries). ~10 archivos con `<img>` nativo pero son admin UI / mascotas / review avatars → bajo impacto perf en rutas públicas.
- **IMG-SIZES**: oportunidad de revisar `sizes` en ServiceCard explorar (H4).
- **IMG-CLS**: oportunidad de revisar galería ficha + reviews para dimensiones consistentes.

### Bundles JS

**Top 5 bundles del último build local**:

| Chunk | Tamaño gzip approx | Qué lleva |
|---|---:|---|
| `main-*.js` | ~292 KB | React + Next runtime + context providers + libs |
| `25f4ac2a.*.js` | ~148 KB | Framework chunk (Next internals) |
| `framework-*.js` | ~140 KB | React scheduler, reconciler |
| `4978-*.js` | ~120 KB | Posible: Leaflet (mapas) o Supabase client — verificar |
| `polyfills-*.js` | ~112 KB | Browsers viejos |

**Observaciones**:
- `polyfills` 112 KB → verificar si se puede recortar con target más moderno (`.browserslistrc` actualizar a last 2 versions).
- `4978-*.js` 120 KB → identificar en bundle analyzer. Si es Leaflet, mover a dynamic import.
- `main` 292 KB es razonable para una app con context providers (UserContext, servicios, etc.).

**Esfuerzo recorte bundle**: instalar `@next/bundle-analyzer` + `ANALYZE=true npm run build` + decidir qué recortar. 1-2h + testing. **Post-launch**.

### CSP + preconnect

- **PRECONNECT**: Supabase Storage + Unsplash ya con preconnect en `_document.tsx`. Óptimo.
- **PRECONNECT-FALTANTE**: no hay preconnect a `fonts.gstatic.com` (fuentes self-hosted ya no lo necesitan), ni a GA4 (opcional).

### Cache + SW

- **PWA-CACHE**: `next-pwa` con runtime caching defaults. Óptimo para navegación repetida.
- **SW-DEMOLISHER**: staging/preview usa SW demoledor — no impacta prod.

## Top 5 fixes pre-launch (impacto >20% esfuerzo <2h)

Ranking por impacto/costo:

### P1 — Diagnosticar + fix CLS mobile ficha 0.187

**Estado**: CLS 0.187 mobile (POBRE). Afecta ranking SEO de la página core del producto.

**Acción**:
1. El PO corre `npx lighthouse https://www.pawnecta.com/servicio/<uuid> --form-factor=mobile --output=json --output-path=./ficha-mobile.json` (viernes 20-11 AM, 2 min).

3. Fix según causante: agregar `width`/`height` o `aspect-ratio` CSS.
4. Medir en preview + mergear (regla "fix de rendimiento se mide en preview antes del merge").

**Esfuerzo**: 45-60 min (incluye medición antes y después).
**Impacto esperado**: CLS 0.187 → <0.1 (verde). Impacto directo en Perf score + SEO.

### P2 — `sizes` optimizado en ServiceCard de /explorar

4. Medir preview + mergear.

**Esfuerzo**: 20 min + 10 min medición.
**Impacto esperado**: LCP mobile 5.8s → 4-4.5s.

### P3 — Asegurar `min-height` en skeleton ReviewList

**Estado**: posible causa de CLS en ficha mobile cuando reviews cargan.

**Acción**:
1. Abrir [components/Service/ReviewList.tsx](../../components/Service/ReviewList.tsx).

**Esfuerzo**: 25 min.

**Estado**: LCP amarillo. Umbral verde: <2.5s.

**Acción**:

**Esfuerzo**: 30-40 min (medición + fix + re-medición).
**Impacto esperado**: LCP home-mobile 3.5s → 2.3-2.8s.

### P5 — Verificar `priority` en 1er slide del carrusel home

**Estado**: si home-carrusel aterrizó post-11-17, el priority puede estar en todos los slides.

**Esfuerzo**: 15 min.
**Impacto esperado**: perf home-mobile 90 → 92-93. Marginal pero gratis.

**Total esfuerzo P1-P5**: ~2h 15 min. Realistic para viernes 20-11 AM pre-freeze si hay ventana.

## Top 5 fixes post-launch (impacto significativo, esfuerzo >2h)

### P6 — Bundle recorte vía dynamic import de Leaflet

**Estado**: `4978-*.js` ~120 KB posible candidato Leaflet.

**Acción**: dynamic import con `ssr: false` + Suspense fallback. Leaflet solo carga en páginas con mapa.

**Esfuerzo**: 2-3h.
**Impacto esperado**: -80 KB en navegación inicial a rutas sin mapa.

### P7 — SSR para `/mensajes` lista inicial

**Estado**: lista de conversaciones es client-only post-mount.

**Acción**: migrar a `getServerSideProps` o Server Component patterns. Reduce time-to-interactive.

**Esfuerzo**: 3-4h.
**Impacto esperado**: interactividad `/mensajes` -500-800ms.

### P8 — Bundle analyzer + recorte main

**Estado**: `main-*.js` 292 KB. Puede incluir libs que se usan en 1-2 rutas.

**Acción**: `@next/bundle-analyzer` + decisiones por lib.

**Esfuerzo**: 4-6h.
**Impacto esperado**: -50-100 KB.

### P9 — Compresión server-side de fotos subidas por proveedor

**Estado**: `UPLOAD-IMG-RESIZE` ítem BACKLOG. Hoy los proveedores suben fotos sin resize → viajan tal cual.

**Acción**: endpoint intermediario que comprima via `sharp` + sube a Supabase Storage resized.

**Esfuerzo**: 4-6h.
**Impacto esperado**: LCP mobile de todas las páginas que muestran fotos baja ~1s.

### P10 — HTTP/2 push o 103 Early Hints

**Estado**: Vercel soporta Early Hints en Pro. No configurado hoy.

**Acción**: configurar Early Hints para fonts + hero images en rutas críticas.

**Esfuerzo**: 2-3h.
**Impacto esperado**: LCP -200-400ms en cold navigation.
