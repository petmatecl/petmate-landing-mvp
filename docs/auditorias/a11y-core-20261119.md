## Categorías WCAG AA relevantes

| Criterio WCAG | Nivel | Qué requiere |
|---|---|---|
| 1.1.1 Non-text Content | A | `alt` en toda imagen con contenido; alt vacío `""` en decorativas |
| 1.3.1 Info and Relationships | A | Labels asociados a inputs via `htmlFor`/`id`; landmarks ARIA; headings jerárquicos |
| 1.4.3 Contrast Minimum | AA | Texto normal ≥4.5:1; texto grande (≥18pt o ≥14pt bold) ≥3:1 |
| 1.4.11 Non-text Contrast | AA | Elementos UI (borders, íconos interactivos) ≥3:1 vs adyacente |
| 2.1.1 Keyboard | A | Todo funcional accesible por teclado |
| 2.4.3 Focus Order | A | Orden tabular lógico |
| 2.4.7 Focus Visible | AA | Foco de teclado visible (outline o ring) |
| 3.3.2 Labels or Instructions | A | Labels + placeholder no sustituye label |
| 4.1.2 Name, Role, Value | A | `aria-label`, `aria-labelledby`, `role` en custom controls |
| 4.1.3 Status Messages | AA | `role="status"` o `aria-live` en toasts, errores |

## Hallazgos por URL

### 1. Home `/`

**Cosas bien** (verificado en código):
- `pages/_document.tsx` tiene `<Html lang="es">` → OK WCAG 3.1.1.
- `components/Header.tsx` usa `aria-label="Navegación principal"` en `<nav>` + `aria-label` en burger menu (líneas 204, 402, 435) → OK.

**Hallazgos**:

- **A11Y-H-01 [AA]** — Contraste `text-slate-400` sobre `bg-white`. Grep muestra 100+ usos. Slate-400 (#94A3B8) sobre white da ratio ~3.2:1 → **FALLA AA para texto normal** (requiere 4.5:1). Usos típicos: placeholder, texto secundario de cards.
- **A11Y-H-02 [AA]** — Contraste `text-accent-500` (#22C55E) sobre `bg-white`: ratio ~2.3:1 → **FALLA AA**. El tailwind config advierte usar `accent-600` para texto pero hay 50+ usos de `text-accent-500` en el código.
- **A11Y-H-03 [AA]** — `focus:outline-none` en 70 call sites (18 archivos). **Si no van acompañados de `focus:ring-*`**, el foco de teclado queda invisible. Verificar grep caso por caso.

**Impacto**:
- A11Y-H-01 texto secundario ilegible para users con baja visión en condiciones de luz brillante.
- A11Y-H-02 CTAs y highlights verdes ilegibles sin fondo oscuro.
- A11Y-H-03 user tabulando no sabe qué elemento está activo → bloquea navegación por teclado.

### 2. Explorar `/explorar`

**Cosas bien**:
- Chip filtros con aria-label implícito (verificar).
- SearchBar en header usa combobox pattern.

**Hallazgos**:

- **A11Y-E-01 [AA]** — Botón `×` de dismiss chip usa texto literal `×` sin `aria-label`. El lector de pantalla lee "x" sin contexto. Ver [pages/explorar.tsx:751](../../pages/explorar.tsx#L748-L752).
- **A11Y-E-02 [A]** — Grilla de servicios usa `<article>` para cards? Verificar. Si usa `<div>` crudo, falta semántica.
- **A11Y-E-03 [AA]** — Estado "No se pudieron cargar los servicios" (línea 760) no tiene `role="alert"` ni `aria-live`. Users con lector no se enteran que apareció un error tras la navegación.
- **A11Y-E-04 [A]** — Skeleton loader `ServiceSkeleton` no indica `aria-busy="true"` al contenedor + no tiene texto para lector.

### 3. Perfil proveedor `/proveedor/{id}`

**Hallazgos (estáticos)**:

- **A11Y-P-01 [A]** — Verificar que foto de perfil tiene `alt="Foto de perfil de {nombre}"` o similar. Si está vacío o genérico ("foto"), lector no identifica.
- **A11Y-P-02 [A]** — Galería de servicios lista con `<ul>`/`<li>` o solo `<div>`? WCAG prefiere semántica de lista.
- **A11Y-P-03 [AA]** — Botón "Contactar" + botón "WhatsApp" + botón "Llamar" (si visibles) deben tener `aria-label` descriptivo con el nombre del proveedor ("Contactar a {nombre}").

### 4. Ficha servicio `/servicio/{id}`

**Cosas bien**:
- `ServiceDetailView.tsx` tiene header jerárquico (h1 título + h2 secciones).
- `aria-label` en navegación de galería (buscar).
- Reviews usan `article` semántico (verificar).

**Hallazgos**:

- **A11Y-S-01 [AA]** — Galería arrows (líneas 913, 921 — buttons con solo SVG `<polyline>`) sin `aria-label`. Usuario lector no sabe qué hace cada botón.
- **A11Y-S-02 [A]** — Miniaturas (línea 961) tienen `alt="Miniatura foto ${i + 1}"` → OK semánticamente, aunque mejor sería "Foto X de Y del servicio".
- **A11Y-S-03 [AA]** — Modal "Reservar" (`SolicitarAgendamientoModal.tsx`) usa `focus:outline-none` repetido (9 veces). Verificar que tiene `focus:ring` acompañando.
- **A11Y-S-04 [AA]** — Modal debe trap focus al abrir + restore focus al cerrar. Verificar implementación (headlessui o custom).
- **A11Y-S-05 [AA]** — Botón "Reservar" + "Enviar Mensaje" tienen suficiente contraste (`bg-accent-600` ratio 4.7:1 con white) → OK.
- **A11Y-S-06 [AA]** — Estrellas de rating usan SVG. Verificar `role="img"` + `aria-label="4 de 5 estrellas"` en el wrapper. Sin esto, lector lee "star star star" o nada.
- **A11Y-S-07 [AAA opcional]** — Alertas de errores en el modal de reserva deben tener `role="alert"`.

### 5. Mensajes `/mensajes`

**Hallazgos (estáticos)**:

- **A11Y-M-01 [A]** — Lista de conversaciones: ítems activos (conversación seleccionada) deben indicarse con `aria-current="true"` o `aria-selected="true"` según el patrón usado.
- **A11Y-M-02 [AA]** — "Cargando..." sin `aria-live="polite"` — lector no anuncia el estado.
- **A11Y-M-03 [AA]** — Nuevos mensajes entrantes (realtime) deben disparar anuncio al lector via `aria-live="polite"` region, o un ding sonoro.
- **A11Y-M-04 [A]** — Input de texto para enviar mensaje debe tener `<label>` visible o `aria-label="Escribe un mensaje"`.
- **A11Y-M-05 [AA]** — Botón enviar debe tener `aria-label="Enviar mensaje"` si es solo un ícono paper-plane.

## Hallazgos cross-URL

### Contraste (hallazgo sistémico)

**C-01 [AA]** — `text-slate-400` sobre fondo blanco falla AA. Afecta 100+ instancias en el código. Patrón típico: placeholders de inputs, texto secundario de cards.

**Fix**: migrar a `text-slate-500` (ratio ~5.5:1 → OK). Esfuerzo: find/replace cuidadoso + regresión visual. ~1h.

**C-02 [AA]** — `text-accent-500` sobre fondo blanco falla AA. ~50 instancias.

**Fix**: migrar a `text-accent-600` para texto; `accent-500` queda solo para focus rings + decorativo sobre fondo oscuro. ~45 min.

**C-03 [AA]** — `placeholder-slate-400` en varios inputs. Placeholder como etiqueta visual no cumple 4.5:1.

**Fix**: cambiar a `placeholder-slate-500` o mantener label visible + placeholder decorativo. ~30 min.

### Focus visible (hallazgo sistémico)

**F-01 [AA]** — `focus:outline-none` 70 instancias. Verificar que cada una tiene `focus:ring-*` o `focus-visible:ring-*`.

**Fix**: pasada de verificación con grep extendido: `focus:outline-none(?![^"]*focus(?:-visible)?:ring)` para encontrar los que fallan.

### `<Html lang="es">`

**L-01 [A]** — Verificado OK en `pages/_document.tsx:7`.

### Skip link

**SK-01 [AA]** — No hay `<a href="#main">Saltar al contenido</a>` al inicio del body. Lector + teclado ayuda. Hoy no está.

**Fix**: agregar skip link a `_app.tsx` o layout global. ~15 min.

### Toasts y errores

**T-01 [AA]** — `sonner` Toaster probablemente tiene `role="status"` o `aria-live` por default. Verificar.

**T-02 [AA]** — Validación inline de formularios (register, login, password reset): mensajes de error deben tener `aria-describedby` linkeando al input + `aria-invalid="true"` en el input cuando falla.

### Imágenes decorativas

**D-01 [A]** — Varios SVGs decorativos inline (ChevronDown, etc.) no tienen `aria-hidden="true"` → lector los lee como "image" sin propósito. Pasada grep sobre `<svg` sin `aria-hidden` en componentes clave.
